# Legal and consent artifact checklist

These are drafting structures, NOT final legal documents. Colombian privacy counsel and regulatory/clinical reviewers must produce or approve the released text.

## Required artifacts

| Artifact | Purpose | Approval |
|---|---|---|
| Privacy notice | Explain controller, purposes, data, sharing, rights, retention, contact | Privacy counsel |
| Sensitive-health-data authorization | Explicit informed authorization and optionality | Privacy counsel |
| Terms of use | Product terms, availability, account, acceptable use | Counsel |
| Medical limitation notice | Clarify no diagnosis/prescription/emergency guarantee | Clinical + regulatory + counsel |
| Trusted-contact notice | Explain invitations, alert data, acknowledgement, revocation | Privacy counsel |
| Location consent | Event-based sharing, accuracy, recipients, revocation | Privacy counsel |
| Cloud-sync consent | Explain local-only vs cloud processing and transfer | Privacy counsel |
| Data rights procedure | Access, correction, revocation, deletion, complaints | Operations + counsel |
| Vendor/processor agreements | Define processing, security, sub-processors, transfer | Counsel + security |
| INVIMA assessment | Determine device status/classification from intended purpose | Regulatory specialist |

## Publication rules

- Version and effective date every document.
- Store the accepted version/locale and timestamp.
- Make documents accessible before and after acceptance.
- Separate mandatory core processing from optional sync, contact alert, location, and analytics purposes.
- Withdrawal must be as practical as granting consent.
- Materially new purposes require a new opt-in.
